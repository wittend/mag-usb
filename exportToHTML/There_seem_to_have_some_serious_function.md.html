### Analysis of Recent Changes and Regressions

I have analyzed the recent changes to the `mag-usb` project. The regressions are likely caused by commit `466e78f` ("Address PR issues from Mike, Rob, &Claude's second tranche."), which was committed yesterday, June 2, 2026.

#### Key Changes in Commit `466e78f`

*   **Scaling Logic Regression:**
    In `src/main.c`, the formula for calculating magnetic field vectors was changed. It no longer divides the raw values by the Number of Samples (`p->NOSRegValue`).
    *   **Old:** `xyz[0] = (((double)p->XYZ[0] / p->NOSRegValue) / p->x_gain) * 1000;`
    *   **New:** `xyz[0] = ((double)p->XYZ[0] / p->x_gain) * 1000;`
    This will cause output values to be scaled up by a factor equal to `NOSRegValue` (default is usually 1, but if it's higher, the error will be significant).

*   **Default Parameter Changes:**
    Default values for sensor configuration were changed in `src/main.c`:
    *   **Cycle Counts (CC):** Changed from `400` to `200` (`CC_200`).
    *   **Gains:** Changed from `150` to `75` (`GAIN_75`).

*   **Active Hardware Initialization:**
    Functions like `setCycleCountRegs`, `readCycleCountRegs`, and `setNOSReg` in `src/magdata.c` were converted from stubs/commented-out code to active functions that write to the I2C hardware. If the hardware is not connected or behaves unexpectedly, this could lead to new error states or initialization failures.

*   **Configuration File Handling:**
    *   A new `-f <path>` flag was added to specify a custom TOML configuration file.
    *   The magnetometer I2C address can now be overridden via the `-A <hex>` command-line flag.

*   **Version Update:**
    The software version was bumped from `0.0.6` to `0.0.8`.

#### Recommendation
If the output values seem "too large" or "incorrectly scaled," the removal of `p->NOSRegValue` from the calculation in `src/main.c` is the most probable cause. Reverting this specific line or ensuring `p->NOSRegValue` is correctly handled according to the RM3100 datasheet is advised.
